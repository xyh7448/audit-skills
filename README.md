# 项目代码审计官 Skills

一套标准化的 AI Agent 审计技能集，让 Agent 按照固定方法论自动检查系统质量。

## 为什么需要这套 Skills？

大多数人在让 AI Agent 写代码，但真正缺的不是编码能力，而是一套**标准化审计体系**。

有了这套 Skills，Agent 会自动完成：

```
开发 → 审计 → 对齐 → 验证数据源 → 修复 → CTO评审 → 上线
```

## 6 个命令

| 命令 | 用途 | 使用时机 |
|------|------|---------|
| `/audit-feat <模块名>` | 功能全景审计（八维评分） | 开发完一个功能后 |
| `/audit-febe <模块名>` | 前后端对齐审计（API/字段/类型） | 联调或发现数据不对时 |
| `/audit-data <模块名>` | 数据源真实性审计（逐字段溯源） | 发现数据可疑时 |
| `/audit-prod <模块名>` | 生产就绪审计（0-105 分量化） | 上线前 |
| `/cto <模块名>` | CTO 终审（A/B/C 等级判定） | 每次开发结束后 |
| `/fix <模块名>` | 规划修复 → 执行 → 验收 | 审计发现问题后 |

## 推荐执行顺序

```
/audit-feat → /audit-febe → /audit-data → /audit-prod → /fix → /cto
```

## 各 Skill 详解

### `/audit-feat` — 功能全景审计

以资深系统架构师视角，对功能模块进行八维审计：

1. **功能完整性** — TODO/FIXME、空实现、Mock 数据
2. **架构合理性** — 分层规范、重复实现、职责混乱
3. **数据流** — 输入→处理→输出全链路追踪，含静默清空检测
4. **API 层** — RESTful 规范、参数校验、返回格式
5. **服务层** — 拆分合理性、循环依赖
6. **数据库层** — 表结构、索引、迁移同步
7. **异常处理** — 覆盖率、错误码、用户友好性
8. **性能问题** — N+1 查询、重复请求、阻塞

输出加权综合评分 + 风险清单 + 修复优先级。

### `/audit-febe` — 前后端对齐审计

逐个核对前后端是否完全对齐：

- API 接口（URL / Method / 参数 / 返回）
- 字段一致性（缺失 / 多余 / 命名不一致）
- 类型一致性（str vs number、Optional vs null）
- Jinja2 Context 变量追踪
- WebSocket 消息格式对齐
- Mock / 假数据检测

### `/audit-data` — 数据源真实性审计

**核心理念：用户看到的每一个数字，都必须能追溯到真实数据源。**

逐字段反向追踪：`用户看到 → 前端变量 → API → Service → 数据获取层 → 最终数据源`

数据源分类：🟢 Live API / 🟢 DB Cache / 🟡 Stale Cache / 🔴 Hardcoded / 🔴 Mock/Fake

按模块类型（出海评估/聊天客服/广告投放）提供针对性检查表。

### `/audit-prod` — 生产就绪审计

11 个维度量化评分（总分 105）：

| 维度 | 分值 |
|------|------|
| 安全 | 15 |
| 权限控制 | 10 |
| 缓存策略 | 10 |
| 日志与可观测性 | 10 |
| 限流与熔断 | 10 |
| 异常处理 | 10 |
| 数据库 | 10 |
| 部署配置 | 10 |
| 环境变量 | 5 |
| 成本风险 | 10 |
| 异步安全 | 5 |

上线判定：≥89 分可上线，74-88 分修复后上线，<74 分禁止上线。

### `/cto` — CTO 终审

以 CTO 视角判断是否达到商业上线标准，七维评估：

1. 用户价值（20%）
2. 数据真实性（25%）— 权重最高，数据造假一票否决
3. 技术架构（15%）
4. 扩展能力（10%）
5. 维护成本（10%）
6. 商业可行性（10%）
7. 风险评估（10%）

输出 A 级（直接上线）/ B 级（小规模测试）/ C 级（禁止上线）。

**强制前置**：执行 `/cto` 前必须先跑 `/audit-feat` 和 `/audit-data`。

### `/fix` — 审计问题修复

四阶段闭环修复工作流：

1. **收集问题** — 汇总所有审计报告的问题
2. **规划修复** — 按 P0/P1/P2 排序，输出修复计划表
3. **用户确认** — 必须确认后才动手（安全阀）
4. **逐项修复** — 改一项验一项，每项立即验证
5. **验收测试** — 回归检查 + 功能验证 + 测试执行

## 安装

将 skills 目录复制到你的项目：

```bash
# 作为项目级 Skills（推荐）
cp -r audit-feat audit-febe audit-data audit-prod cto fix .qoder/skills/

# 或作为个人全局 Skills
cp -r audit-feat audit-febe audit-data audit-prod cto fix ~/.qoder/skills/
```

## 目录结构

```
qoder-audit-skills/
├── audit-feat/SKILL.md    # 功能全景审计
├── audit-febe/SKILL.md    # 前后端对齐审计
├── audit-data/SKILL.md    # 数据源真实性审计
├── audit-prod/SKILL.md    # 生产就绪审计
├── cto/SKILL.md           # CTO 终审
└── fix/SKILL.md           # 修复工作流
```

## 适用场景

这套 Skills 最初为 Alpha Global Pro（智能出海决策平台）设计，但其审计方法论是通用的，适用于任何 FastAPI + Jinja2/React 全栈项目。
