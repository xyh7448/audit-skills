# 生产级就绪审计（Production Readiness Audit）

你是一名生产环境运维专家。请对指定功能模块进行上线前全面检查，输出量化评分。

## 触发方式

```
/audit-prod <module-name>
```

示例：`/audit-prod export-assessment`、`/audit-prod chat`

## 审计维度与评分标准

### 1. 安全（15 分）

| 检查项 | 分值 | 方法 |
|--------|------|------|
| API 认证/鉴权 | 5 | 检查路由是否有认证保护（如 `Depends(get_current_user)`、`@login_required`、JWT 中间件等） |
| SQL 注入防护 | 3 | 检查是否有 raw SQL、`text()` 拼接 |
| XSS 防护 | 2 | 检查模板是否自动转义、`|safe`/`dangerouslySetInnerHTML` 使用 |
| 敏感信息泄露 | 3 | 检查日志/错误响应是否暴露 API Key、内部路径 |
| CORS 配置 | 2 | 检查 CORS 中间件配置 |

### 2. 权限控制（10 分）

| 检查项 | 分值 |
|--------|------|
| 用户只能访问自己的数据 | 5 |
| 多角色权限隔离（如 Admin/User） | 5 |

### 3. 缓存策略（10 分）

| 检查项 | 分值 |
|--------|------|
| Redis 缓存有 TTL | 3 |
| 缓存失效/更新策略 | 3 |
| 无缓存穿透风险 | 2 |
| 缓存与 DB 一致性 | 2 |

### 4. 日志与可观测性（10 分）

| 检查项 | 分值 |
|--------|------|
| 关键操作有日志 | 3 |
| 日志级别合理（info/warning/error） | 2 |
| 结构化日志（包含 request_id 等） | 2 |
| Prometheus 指标暴露 | 3 |

### 5. 限流与熔断（10 分）

| 检查项 | 分值 |
|--------|------|
| API 限流（rate limit） | 3 |
| 外部 API 调用有超时 | 3 |
| LLM 调用有超时和重试 | 2 |
| 熔断/降级策略 | 2 |

### 6. 异常处理（10 分）

| 检查项 | 分值 |
|--------|------|
| 全局异常处理 | 3 |
| 业务异常有明确错误码 | 3 |
| 无裸 `except:` | 2 |
| 用户可见错误信息友好 | 2 |

### 7. 数据库（10 分）

| 检查项 | 分值 |
|--------|------|
| 有索引覆盖高频查询 | 3 |
| 连接池配置合理 | 2 |
| Alembic/Prisma/Django 迁移同步 | 3 |
| 无大事务/长锁 | 2 |

### 8. 部署配置（10 分）

| 检查项 | 分值 |
|--------|------|
| Dockerfile 配置正确 | 2 |
| docker-compose 服务完整 | 2 |
| 环境变量有文档（`.env.example` 或类似） | 3 |
| 启动脚本/健康检查 | 3 |

### 9. 环境变量（5 分）

| 检查项 | 分值 |
|--------|------|
| 所有必要变量有默认值或文档 | 2 |
| 无硬编码的 Key/URL | 2 |
| 配置集中管理（如 `config.py`、`.env`、`settings.ts`） | 1 |

### 10. 成本风险（10 分）

| 检查项 | 分值 |
|--------|------|
| LLM 调用有 token 限制 | 3 |
| 外部 API 调用有频率控制 | 3 |
| 大数据处理有分页/批处理 | 2 |
| 无无限循环/递归风险 | 2 |

### 11. 异步安全（5 分）

用 `Grep` 搜索模块文件中的异步反模式：

| 检查项 | 分值 | 搜索模式 |
|--------|------|--------|
| async 函数中无同步阻塞调用 | 2 | `time\.sleep\|requests\.\|\.read()\|open(` 在 `async def` 内 |
| DB 查询使用异步接口 | 2 | `session\.query\|session\.execute` 在 `async def` 内应用 `await` |
| 无事件循环阻塞 | 1 | `while True.*sleep\|long_running` 无 `await` |

## 审计流程

1. **文件扫描**：用 `SearchCodebase` + `Grep` 定位模块相关文件
2. **逐项检查**：按上述 11 个维度逐一检查
3. **评分计算**：每项给 0 / 部分分 / 满分
4. **问题记录**：每个扣分项记录具体文件和原因

## 输出格式

```markdown
# [模块名] 生产就绪审计报告

## Production Score: XX / 100

### 评分明细

| 维度 | 得分 | 满分 | 评价 |
|------|------|------|------|
| 安全 | X | 15 | ... |
| 权限控制 | X | 10 | ... |
| 缓存策略 | X | 10 | ... |
| 日志与可观测性 | X | 10 | ... |
| 限流与熔断 | X | 10 | ... |
| 异常处理 | X | 10 | ... |
| 数据库 | X | 10 | ... |
| 部署配置 | X | 10 | ... |
| 环境变量 | X | 5 | ... |
| 成本风险 | X | 10 | ... |
| 异步安全 | X | 5 | ... |
| **总计** | **XX** | **105** | |

### 上线判定

- **≥ 89 分**：✅ 可以上线
- **74-88 分**：⚠️ 需要修复高风险项后上线
- **< 74 分**：🚫 禁止上线

### 高风险项（必须修复）
| # | 问题 | 维度 | 影响 | 修复建议 |
|---|------|------|------|---------|

### 中风险项（建议修复）
| # | 问题 | 维度 | 影响 | 修复建议 |
|---|------|------|------|---------|

### 检查清单
- [ ] 所有环境变量已配置
- [ ] 数据库迁移已执行
- [ ] 日志输出已验证
- [ ] 健康检查已通过
- [ ] 回滚方案已准备
```

## 注意事项

- 严格打分，不要放水；生产事故的成本远高于延期上线
- 如果项目有 LLM 调用，重点关注 Token 成本和超时重试放大效应
- 检查项目中的关键超时配置环境变量
- 检查 Worker/后台进程/定时任务的异常恢复机制
- 如果项目有多角色系统，检查权限隔离是否符合项目规范
